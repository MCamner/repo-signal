# Export Schema Reference

Generated by `repo-signal export`. Produces four symbolic intelligence packs
optimized for mq ecosystem consumers (mq-mcp, mq-agent, mq-hal).

Default output: `.repo-signal/exports/`

---

## Commands

```bash
repo-signal export [path]                    # generate all four packs
repo-signal export [path] --output DIR       # write to custom directory
repo-signal export [path] --symbol-index     # one pack only
repo-signal export [path] --callgraph
repo-signal export [path] --repo-summary
repo-signal export [path] --risk-map
repo-signal export [path] --format json      # machine-readable result summary
```

---

## symbol_index.v1

**File:** `symbol_index.json`

Public symbols, file inventory, and ownership hints.

```json
{
  "schema": "symbol_index.v1",
  "repo_name": "string",
  "generated_at": "ISO-8601",
  "file_count": 0,
  "symbol_count": 0,
  "files": [
    {
      "path": "repo_signal/core.py",
      "extension": ".py",
      "symbol_count": 5,
      "public_symbols": ["Engine", "run"]
    }
  ],
  "symbols": [
    {
      "name": "Engine",
      "kind": "class",
      "file_path": "repo_signal/core.py",
      "line": 12,
      "is_public": true
    }
  ]
}
```

### symbol fields

| Field | Type | Notes |
| ----- | ---- | ----- |
| `name` | string | Symbol name |
| `kind` | string | `class`, `function`, or `shell_function` |
| `file_path` | string | Repo-relative path |
| `line` | int | Line number where symbol is defined |
| `is_public` | bool | `false` if name starts with `_` |

Supported file types: `.py`, `.sh`, `.bash`, `.zsh`

## callgraph.v1

**File:** `callgraph.json`

Import and cross-file relationship graph.

```json
{
  "schema": "callgraph.v1",
  "repo_name": "string",
  "generated_at": "ISO-8601",
  "edge_count": 0,
  "hub_files": ["repo_signal/core/models.py"],
  "imports": {
    "repo_signal/inspect.py": ["repo_signal/core/models.py"]
  },
  "importers": {
    "repo_signal/core/models.py": ["repo_signal/inspect.py", "repo_signal/doctor.py"]
  },
  "edges": [
    {
      "source": "repo_signal/inspect.py",
      "target": "repo_signal/core/models.py",
      "relation": "python_import"
    }
  ]
}
```

### edge relation values

| Value | Description |
| ----- | ----------- |
| `python_import` | `from x import y` or `import x` |
| `shell_source` | `source ./file` or `. ./file` |
| `shell_exec` | `bash ./file` or `sh ./file` |

### hub_files

Files imported by ≥ 3 other files. Listed in descending importer count.
High-hub files have wide blast radius — changes here affect many consumers.

## repo_summary.v1

**File:** `repo_summary.json`

Compact repository context for AI consumers. Designed to be injected
as one-shot context into LLM tools without reading the full repo.

```json
{
  "schema": "repo_summary.v1",
  "repo_name": "string",
  "generated_at": "ISO-8601",
  "version": "1.0.0",
  "description": "string from README",
  "project_type": "Python CLI",
  "languages": { "Python": 45, "Shell": 8 },
  "file_count": 65,
  "test_summary": "8 test files",
  "key_files": ["README.md", "CHANGELOG.md", "pyproject.toml"],
  "entrypoints": ["repo_signal/cli.py"],
  "stable_contracts": ["inspect.v1", "doctor.v1"],
  "top_symbols": ["inspect_repo", "doctor_repo", "build_report"]
}
```

## risk_map.v1

**File:** `risk_map.json`

Structural risk signals. No AI findings, no heuristic scoring — purely
structural observations about code organization and documentation gaps.

```json
{
  "schema": "risk_map.v1",
  "repo_name": "string",
  "generated_at": "ISO-8601",
  "risk_count": 3,
  "risks": [
    {
      "id": "RSK-001",
      "level": "medium",
      "kind": "large_file",
      "file": "repo_signal/cli.py",
      "detail": "1789 lines — consider splitting into focused modules.",
      "structural": true
    }
  ]
}
```

### risk levels

| Level | Description |
| ----- | ----------- |
| `high` | Missing critical structure (no README, no tests) |
| `medium` | Structural concern (large file, high fan-in) |
| `low` | Minor observation |

### risk kinds

| Kind | Trigger |
| ---- | ------- |
| `missing_readme` | `README.md` not present |
| `missing_changelog` | `CHANGELOG.md` not present |
| `no_tests` | No `tests/test_*.py` files |
| `large_file` | Source file > 400 lines |
| `high_fan_in` | File imported by ≥ 5 other files |

`structural: true` — every risk in risk_map.v1 is structural. This field
exists to distinguish this schema from AI-generated finding schemas.

## mq-mcp integration

The export packs are designed for consumption by
`callgraph_builder._try_merge_repo_signal_packs()` in mq-mcp.
When the packs exist on disk, mq-mcp's callgraph builder merges them
automatically into `review_engine/context/callgraph.json`.

Expected paths:
```
.repo-signal/exports/symbol_index.json
.repo-signal/exports/callgraph.json
.repo-signal/exports/repo_summary.json
.repo-signal/exports/risk_map.json
```

---

## Stability

Schemas stable from v1.1.0. New fields may be added in minor versions.
Field removals and renames require a schema version bump.
Schema version is always present in every output file.
