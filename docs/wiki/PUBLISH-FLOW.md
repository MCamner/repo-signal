# Wiki Publish Flow

How to move generated wiki exports into the live GitHub Wiki.

## Overview

`repo-signal wiki export` writes reviewable Markdown files locally.  
They are never pushed automatically. You review them, then copy them to the GitHub Wiki manually.

## Step 1 — Export

```bash
repo-signal wiki export . --output docs/wiki-export
```

This writes files to `docs/wiki-export/`:

```text
docs/wiki-export/
├── Home.md
├── Getting-Started.md
├── Command-Reference.md
├── Architecture.md
├── Roadmap.md
├── Release-Flow.md
├── Skills.md
└── Troubleshooting.md
```

## Step 2 — Review

Pages are generated from the target repo's tracked files, and a page whose
source is missing says so rather than inventing content. Review anyway before
publishing — a page can faithfully reproduce a document that is itself stale:

```bash
cat docs/wiki-export/Home.md
cat docs/wiki-export/Command-Reference.md
```

Edit any file that needs corrections, or fix the source document and re-export.
Prefer the second: pages are regenerated, so edits made here are lost on the
next export.

## Step 3 — Clone the GitHub Wiki

GitHub Wiki is a separate git repo. Clone it once:

```bash
git clone https://github.com/<user>/<repo>.wiki.git ~/repo-signal.wiki
```

## Step 4 — Copy and push

```bash
cp docs/wiki-export/*.md ~/repo-signal.wiki/
cd ~/repo-signal.wiki
git add .
git commit -m "docs: update wiki from wiki export"
git push
```

The wiki is live immediately after push.

## Refreshing an existing wiki page

If the wiki page already exists and you want to update only changed pages, use `diff` first:

```bash
diff docs/wiki-export/Command-Reference.md ~/repo-signal.wiki/Command-Reference.md
```

Copy only the files with meaningful changes.

## Notes

- The GitHub Wiki repo URL pattern is: `https://github.com/<user>/<repo>.wiki.git`
- GitHub Wiki does not support subdirectories — all pages must be at the root
- The wiki sidebar is controlled by `_Sidebar.md` (not generated by `wiki export`)
- Always review before pushing — wiki history is linear and there is no PR review step
